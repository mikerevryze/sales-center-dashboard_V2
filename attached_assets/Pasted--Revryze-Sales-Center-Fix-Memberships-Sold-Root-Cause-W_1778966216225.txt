# Revryze Sales Center — Fix Memberships Sold (Root Cause: Won Opps Truncated by 500 Cap)

The "Memberships Sold" metric is dramatically undercounted because the opportunities fetcher hits a hard 500-opp cap per pipeline. GHL returns opps newest-first across ALL stages, so for a presale pipeline with thousands of leads, the older Closed Won deals get silently dropped off the end of pagination. Fix that, decouple sold from the date filter, and correct two rep IDs.

Apply ALL changes in one pass.

## Change 2 — Fetch ALL won opps separately with `status=won` filter (root cause fix)

This is the headline fix. GHL's opportunities API supports filtering by status server-side. Use that to guarantee every Closed Won deal is fetched, completely independently from the regular all-opps pagination.

### New helper in `server.js` — add right next to `fetchAllOpportunities()`:

```javascript
// Fetch EVERY won opportunity for a location/pipeline. No 500 cap.
// Uses the GHL `&status=won` filter so pagination is never consumed by leads in other stages.
async function fetchAllWonOpportunities(locationId, pipelineId, headers) {
  let allWon = [];
  let startAfterId = null;
  let keepGoing = true;

  while (keepGoing) {
    let url = `${GHL_API}/opportunities/search?location_id=${locationId}&status=won&limit=100`;
    if (pipelineId) url += `&pipeline_id=${encodeURIComponent(pipelineId)}`;
    if (startAfterId) url += `&startAfterId=${encodeURIComponent(startAfterId)}`;

    let data;
    let attempt = 0;
    while (attempt < 3) {
      attempt++;
      const r = await fetch(url, { headers });
      if (r.status === 429) { await sleep(attempt * 3000); continue; }
      if (!r.ok) { keepGoing = false; break; }
      data = await r.json();
      break;
    }
    if (!data) break;

    const opps = data.opportunities || [];
    allWon = allWon.concat(opps);
    console.log(`[wonOpps] ${locationId}${pipelineId ? '/' + pipelineId : ''} won page fetched ${opps.length}, total won: ${allWon.length}`);

    if (opps.length < 100) keepGoing = false;
    else {
      startAfterId = opps[opps.length - 1].id;
      await sleep(250);
    }

    // Sanity ceiling — if we ever hit this, log a warning but don't pretend the data is complete
    if (allWon.length >= 5000) {
      console.warn(`[wonOpps] ${locationId} hit 5000 won-opp safety ceiling — data may be incomplete`);
      keepGoing = false;
    }
  }

  return allWon;
}
```

### Update `/api/locations/:locationId/opportunities` to use the new helper

Inside that endpoint, after fetching the regular all-opps array (keep the existing logic — that data is still needed for the pipeline funnel and other features), do a second pass with the new helper that fetches every won opp, then merge with dedupe by `id`:

```javascript
// Fetch the regular all-opps array first (capped at 500 — fine for pipeline funnel display)
let allOpps = [];
if (!pipelineId && client.pipelines && client.pipelines.length > 0) {
  for (const pipeline of client.pipelines) {
    const pOpps = await fetchAllOpportunities(locationId, pipeline.pipelineId, headers);
    allOpps = allOpps.concat(pOpps);
    await sleep(300);
  }
} else {
  allOpps = await fetchAllOpportunities(locationId, pipelineId || null, headers);
}

// CRITICAL: fetch every won opp separately so none are truncated by the 500 cap
let allWon = [];
if (!pipelineId && client.pipelines && client.pipelines.length > 0) {
  for (const pipeline of client.pipelines) {
    const pWon = await fetchAllWonOpportunities(locationId, pipeline.pipelineId, headers);
    allWon = allWon.concat(pWon);
    await sleep(300);
  }
} else {
  allWon = await fetchAllWonOpportunities(locationId, pipelineId || null, headers);
}

// Merge — won opps take priority (they are the source of truth for sold count)
const byId = new Map();
allWon.forEach(o => byId.set(o.id, o));
allOpps.forEach(o => { if (!byId.has(o.id)) byId.set(o.id, o); });

// Deduplicate
const merged = Array.from(byId.values());
const seen = new Set();
const finalOpps = merged.filter(o => {
  if (seen.has(o.id)) return false;
  seen.add(o.id);
  return true;
});

const wonCount = finalOpps.filter(o => o.status === 'won').length;
console.log(`[opps] ${locationId} combined — ${finalOpps.length} total, ${wonCount} won (from ${allWon.length} won-fetched)`);

const responseData = { opportunities: finalOpps, total: finalOpps.length, wonTotal: wonCount };
oppsCache.set(cacheKey, { data: responseData, timestamp: Date.now() });
res.json(responseData);
```

### Defensive: also match by stage name

In case any won opps come back with `status: "open"` but live in a "Closed Won" stage (rare GHL edge case), make the `status === 'won'` check more forgiving. In `public/app.js`, add a helper at the top of the file:

```javascript
function isWonOpp(o) {
  if ((o.status || '').toLowerCase() === 'won') return true;
  const stageName = (o.pipelineStageName || '').toLowerCase();
  if (stageName === 'closed won' || stageName === 'won' || stageName.includes('closed won')) return true;
  return false;
}
```

Replace every existing `(o.status || '').toLowerCase() === 'won'` check in `app.js` with `isWonOpp(o)`. This includes `filteredWonOpps()`, `getWonDate()`, `buildContactMaps()`, the rep profile stats block in `openRepProfile()`, and any other spot.

## Change 3 — Decouple Memberships Sold from the date filter

A sold membership stays sold regardless of when it closed. The date filter must NOT touch the Memberships Sold or Revenue Closed numbers — only activity metrics (calls, talk time, close rate).

### `filteredWonOpps()` in `app.js`

Remove the `lastStageChangeAt` cutoff filter. The function becomes:

```javascript
function filteredWonOpps() {
  return appData.opportunities.filter(o => {
    if (!isWonOpp(o)) return false;
    if (ccFilters.clientId !== 'all' && o.locationId !== ccFilters.clientId) return false;
    if (ccFilters.pipelineId !== 'all' && o.pipelineId !== ccFilters.pipelineId) return false;
    if (myViewRepId && getOppRepId(o) !== myViewRepId) return false;
    return true;
  });
}
```

### Close Rate stays date-windowed on BOTH sides

In `renderCommandCenter()`, compute a separate `dateWindowedWonCount` for the close-rate calculation only:

```javascript
const cutoff = getDateCutoff(ccFilters.days);
const dateWindowedWon = wonOpps.filter(o => {
  const d = parseDate(o.lastStageChangeAt);
  return d && d >= cutoff;
});
// Close Rate = (won opps in date window) / (unique contacts called in date window) × 100

let closeRate = '—';
if (uniqueContactsCalled > 0) {
  const raw = (dateWindowedWon.length / uniqueContactsCalled) * 100;
  if (raw <= 100) closeRate = raw.toFixed(1) + '%';
}
```
